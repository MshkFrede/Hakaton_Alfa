## Ручные сценарии

### ТК-1. Автоодобрение и выдача (основной сценарий, ~2 мин)
1. Войти как **Анна (Ромашка)** → «Новая заявка на кредит».
2. Задача: «Закрыть кассовый разрыв». Сумма 3 000 000 → выбрать **Экспресс-кредит** («Рекомендуем»).
3. Срок 24 мес., выручка 60 000 000. Калькулятор показывает зелёную нагрузку.
4. Телефон, согласие БКИ → «Отправить заявку».
5. **Ожидание:** трекер последовательно проходит «Проверка данных» → «Решение», через ~5–10 с статус «Одобрено», условия = запрошенным.
6. «Принять и перейти к подписанию» → ввести показанный код → «Подписать».
7. **Ожидание:** «Договор подписан» → через ~2 с «Средства выданы», номер счёта замаскирован. История содержит все шаги.

### ТК-2. Контрпредложение
1. **Дмитрий (Вектор)**: «Закупить товар или сырьё», 10 000 000 → **Оборотный кредит**, 24 мес., выручка 12 000 000.
2. На шаге параметров калькулятор показывает красную нагрузку и «комфортную сумму».
3. **Ожидание:** статус «Одобрено на других условиях». Сумма меньше, срок 36 мес., прежние значения зачёркнуты.
4. Принять → подписать → выдано, или «Отказаться» → «Вы отказались от предложения».

### ТК-3. Ручной разбор, дозапрос документов, решение специалиста
1. **Игорь (Северов)**: «Закрыть кассовый разрыв», 1 500 000 → Экспресс, 24 мес., выручка 9 000 000 → отправить.
2. **Ожидание:** «На рассмотрении у специалиста».
3. Выйти → **Ольга (банк)**. В очереди «На разборе» есть заявка с рейтингом C.
4. Открыть заявку. Вкладка «Скоринг»: балл 540, разбивка факторов (−40 за просрочки). Вкладка «Внешние данные»: в БКИ микрозайм.
5. «Взять в работу» → «Запросить документы» → отметить «Выписка по расчётному счёту» → комментарий → отправить.
6. Выйти → **Игорь**. На главной баннер «Требуется ваше действие». В заявке загрузить любой файл (PDF/CSV/PNG).
7. **Ожидание:** заявка сама возвращается в «На рассмотрении у специалиста».
8. **Ольга**: вкладка «Документы» — файл скачивается. «Изменить условия» → 1 200 000, 24 мес. → платёж пересчитывается → отправить.
9. **Игорь**: принять → подписать → выдано.
10. **Ольга**, вкладка «Журнал»: все действия, включая внутренние комментарии с пометкой «видно только банку».

### ТК-4. Отказ по стоп-фактору
1. **Сергей (Горизонт)**: любая заявка (например, Оборотный 5 млн / 24 мес., выручка 31 млн).
2. **Ожидание:** автоматический «Отказ» с нейтральной формулировкой для клиента. У специалиста — стоп-факторы «Текущая просрочка 120 дней», «Налоговая задолженность более 1 млн ₽».

### ТК-5. Недоступный внешний источник
1. **Ирина (Туман)**: Экспресс 2 000 000 / 12 мес., выручка 24 000 000.
2. **Ожидание:** обработка длится дольше (таймаут и повторы БКИ), затем «На рассмотрении у специалиста».
3. У специалиста: источник БКИ с бейджем «ошибка» и числом попыток. Причина ручного разбора — «Нет данных из источников: [BKI]».
4. *Вариант:* сделать отказ источника для любой компании:
   `curl -X PUT localhost:8090/admin/sources/FNS -d '{"mode":"ERROR"}'` (вернуть: `"mode":"OK"`).

### ТК-6. Онбординг нового клиента
1. **Алексей (Ладога)** — компании нет. Ввести ИНН `7713056785` → «Найти».
2. **Ожидание:** карточка из ЕГРЮЛ (наименование, ОГРН, руководитель, ОКВЭД, адрес) → «Это моя компания».
3. Подать **Инвестиционный кредит** («Купить оборудование»): всегда уходит специалисту, рейтинг A, рекомендация «одобрить».

## Негативные проверки

| # | Действие | Ожидаемый результат |
|---|---|---|
| Н-1 | Отправить черновик без выручки, телефона или согласия БКИ | `422`, ошибки по полям; в кабинете — «Осталось заполнить: …» |
| Н-2 | Сумма вне лимитов продукта | `422` с допустимым диапазоном |
| Н-3 | Ввести неверный код подписи | `422 «Неверный код подтверждения»`, статус не меняется |
| Н-4 | Клиент открывает заявку другой компании по прямой ссылке | `404` |
| Н-5 | Клиент вызывает `/decision`; специалист вызывает `/submit` | `403` |
| Н-6 | Запрос без токена / с испорченным токеном | `401`, интерфейс переводит на вход |
| Н-7 | Два специалиста одновременно принимают решение (одинаковый `version`) | Первое проходит, второе — `409 VERSION_CONFLICT` |
| Н-8 | Повторная отправка уже отправленной заявки | `200`, текущее состояние, без повторной обработки |
| Н-9 | Принять предложение по заявке в статусе `REJECTED` | `409 INVALID_STATE` |
| Н-10 | Загрузить `.exe` или файл > 10 МБ | `422` / `413` |
| Н-11 | ИНН с неверной контрольной суммой (`7709012345`) | `422 «Некорректный ИНН»` |
| Н-12 | 11 неудачных входов за минуту | `429` |
| Н-13 | Остановить `api` во время обработки (`docker compose restart api`) | После перезапуска задача возвращается в очередь (не позже чем через ~2,5 мин) и доделывается; заявка не «зависает» |
